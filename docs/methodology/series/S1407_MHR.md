## 1. What it is (book definition + figure)

S1407 is the HP(100)-filtered scatter of **Figure 14.16** (book p. 670): real-wage growth `GRWAGEHP100` (y)
against unemployment intensity `ULINTENSITYHP100` (x), 1949–2011, with two-era fitted curves. It is the
**real-wage Phillips curve** analogue of Fig 14.14 (S1405). Per Eq. 14.18, `ẇr/wr = ẏr/yr + f(uInt_L)` —
the real-wage curve = the wage-share (Classical) curve **plus productivity growth**
(`research.methodology_notes[0]`). Shaikh's caption (`research.book_quotes[0]`, p. 670): because
productivity growth *"begins to fall from 1960 until the late 1970s and then gradually rises back to its
original level by 2000… the real wage curve in figure 14.16 departs from [the] 1948 to 1982 fitted
wage-share function in 1960 only to end up back on the new 1994–2011 fitted function in 1999."* Fits ship to
`Technical/data/processed/S1407_phillips_fits.json`.

## 3. Why these sources — Shaikh's rationale + rejected alternatives

- **Why the wage is EC per FTE (NIPA), NOT BLS average hourly earnings.** Shaikh's nominal wage `w =
  EC*100/FEE` is total compensation per full-time-equivalent worker — an *aggregate national-accounts* wage
  consistent with the GDP-deflator price level and the FTE productivity denominator. BLS AHE (a per-worker
  micro wage) would break the Eq. 14.18 identity `ẇr/wr = ẏr/yr + gwsh`. Same reason S1401 must use total
  compensation, applied here to the wage *level*.
- **Why real-GDP-per-FTE productivity, NOT BLS output-per-hour.** The real-wage curve *is* the wage-share
  curve plus productivity growth; if productivity were BLS per-hour, the algebraic decomposition would not
  reconcile with the wage share built from EC and FEE. The code hard-blocks per-hour substitutes at import
  (inherited from S1406; `CH14_review.F8`).
- **Why refit directly rather than derive from the wage-share fit.** The text says conceptually the
  real-wage curve = wage-share fit + HP(productivity growth), but the build **emits a direct refit** and
  notes the algebraic-decomposition reference in a sidecar (`CH14_RESEARCH_SUMMARY.md` line 103) — leaving
  the open question of whether Shaikh's dashed curves were refit or derived (`research.open_questions[0]`).
- **Why the same HP(100) and two-era windows.** Comparability with Fig 14.14 requires identical filter and
  identical 1949–1982 / 1994–2011 windows (`research.methodology_notes[2]`).

## 4. Methodological-change exposure — NIPA drift across three tables + HP endpoint bias

- **Three NIPA tables in the numerator chain.** S1407 rests on T1.10 line 2 (EC), T6.5 (FEE), and T1.1.9
  (deflator) simultaneously — so it carries the *union* of the vintage exposures of S1401, S1406, and the
  wage level. The 2013 IPP capitalization (≈+$400B GDP), 2018 methods, and 2023 reference-year rebasing all
  move at least one of these inputs (`NIPA_CHANGE_TIMELINE.md`).
- **FRED vintage vs frozen 2011 vintage.** Extension re-derives `(A576RC1/B4701C0A222NBEA)/GDPDEF`
  (`research.extension_candidates[0]`) — note the research candidate again lists `A576RC1` for the wage
  numerator, the same mislabel as S1401 §3; the correct mirror is `W209RC1`. No ALFRED pin.
- **HP endpoint bias.** As with S1405, extending 2011→2024 changes filtered values near the splice; re-filter
  end-to-end.
